## Greenhouse Grid: repeat a whole repeated job

The greenhouse is visibly grouped into 3 baseline beds with 4 plots in each bed. The important structure is not just twelve plant actions: finish one bed's four plots, then repeat that bed-sized job for the next bed.

## Predict the inner work before you build

Before building: if there are 3 beds and 4 plots in each bed, how many times should **plant next plot for job job** run altogether? More importantly, which four plant actions belong to the same bed?

In ``||farm(noclick):Farm jobs||``, find ``||farm(noclick):on greenhouse work requested||``, ``||farm(noclick):number of greenhouse beds for job job||``, ``||farm(noclick):plots in each greenhouse bed for job job||``, ``||farm(noclick):move to next greenhouse bed for job job||``, and ``||farm(noclick):plant next plot for job job||``.

Start with one bed-sized job: move to the next bed once, then repeat planting for every plot in that bed. Now put that whole job inside an outer repeat for the number of greenhouse beds.

Run the Greenhouse Grid. Baseline should show four completed plots in one bed before the farm advances to the next bed. A flat total of twelve plant calls is not the same structure, because the supplied world keeps bed context.

## Transfer inspect + if to Healroot

At Defense Prep, Healroot uses the same inspect-and-decide pattern from Animal Meadow. In ``||defenders(noclick):Defender powers||``, find ``||defenders(noclick):on Healroot power requested||``, ``||defenders(noclick):allies to inspect for job job||``, ``||defenders(noclick):inspect next ally for job job||``, ``||defenders(noclick):current ally damaged for job job||``, and ``||defenders(noclick):heal current ally for job job||``.

Repeat through the supplied ally count, inspect first, and heal only when the current ally is damaged. Healthy allies are intentionally skipped.

Baseline inspects 4 allies. The optional upgrade changes the named reporter to 5, so the unchanged algorithm can inspect one more candidate.
