## Orchard Lane: the loop already has a changing number

Four baseline trees visibly need fertilizer levels 1, 2, 3, and 4. This time the changing value should come from the loop itself instead of from a second variable you increase by hand.

## Use the native index

In ``||farm(noclick):Farm jobs||``, find ``||farm(noclick):on orchard work requested||``, ``||farm(noclick):number of orchard trees for job job||``, and ``||farm(noclick):fertilize next tree with value for job job||``. Find the native indexed loop in ``||loops(noclick):Loops||``.

The indexed loop has a counter variable built in. In MakeCode Blocks its first value is `0`, and that value changes automatically each iteration.

Loop from the native zero-based `index` while it is below **number of orchard trees for job job**. Give the fertilizer action `index + 1` so the visible tree levels are 1, 2, 3, 4 rather than 0, 1, 2, 3.

Do not create a second counter. Run Orchard Lane and watch the values on the trees: baseline should be exactly 1 → 2 → 3 → 4.

## Retrieve the resource while pattern for Sunbeam Lily

At Defense Prep, Sunbeam Lily uses a pattern you already built at the Dry Terrace. In ``||defenders(noclick):Defender powers||``, find ``||defenders(noclick):on Sunbeam Lily power requested||``, ``||defenders(noclick):sunlight available at start for job job||``, and ``||defenders(noclick):beam for job job||``.

Make a learner variable named `sunlight`. Copy the starting sunlight reporter into it once. Then use the familiar resource-controlled while pattern so one beam uses one unit of the learner's remaining sunlight.

A full baseline resource can produce 6 beams. The optional upgrade can raise capacity to 8, but an invocation may also begin partly depleted or at zero. The same code should respect the actual starting value reported by the world.
